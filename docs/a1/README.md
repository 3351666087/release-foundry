```powershell
# Dry-run plan, no API key required.

# Mutating probes need --execute, --allow-mutate, and --max-retries 0 after reviewing the dry-run plan.
python -B -m services.runner.api_probe create-run --execute --allow-mutate --max-retries 0 --dataset-id <id> --result-file <run-result.json>

# Safe generation dry-run config for later review. The record includes a preflight summary.
python -B -m services.runner.api_probe create-request --request-name "A1 Tiny Calibration" --request-file docs/a1/api_calibration/tiny_generation_request.json

# Dry-run-first media interface coverage for Text/Audio/File/Image/Video. Real execution requires explicit allowance flags.
python -B -m services.runner.api_probe create-request --request-name "A1 Media Interface Dry Run" --request-file docs/a1/api_calibration/media_interface_request.json
```

Mutating `create-run --execute` and `create-request --execute` require `--allow-mutate` and `--max-retries 0` to avoid duplicate mutation on retry. Real `create-request` execution requires a known positive integer `num_variations` value no larger than `--max-request-variations` and text-only accepted inputs by default. Media generation requires `--allow-media-generation`; non-text accepted inputs require `--allow-non-text-inputs`. Current hosted request quota can block additional generation even when the local preflight passes. The media dry-run record should show `ashr.clone.agent_input.v1`, `parts`, and text/audio/file/image/video part types before any future media execution is considered.

Non-sensitive API calibration notes live in `docs/a1/api_calibration/`. Raw records and screenshots stay in ignored `docs/evidence/private_refs/`.

`services.api.CloudApiService` is local-only and in-memory by default, with JSON snapshot helpers for local replay. It can create tenants/projects/datasets/requests, submit existing A1 `RunResult` payloads, create queued run records, move runs through queued/running/completed/failed/cancelled states, poll stored runs, export A3-consumable run fixtures, and enforce project-scoped quota ledger limits before writes. `services.api.cli run-agent` is the direct fresh-setup smoke path; `services.api.cli run-agent-queued` is the queue-worker smoke path; `queue-run`, `replay-queued`, and `export-fixture` prove persisted queued state can survive process boundaries and still produce deterministic A3 fixtures. Batch queue controls support repeated `--run-id` or generated `--run-count` IDs, deterministic replay by batch order, and per-run fixture/result directories through `--fixture-output-dir` and `--run-output-dir`.
