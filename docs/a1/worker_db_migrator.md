# A1 Worker DB Migrator

`services/api/db_migrator.py` is the executable layer below the canonical data model in `services/api/data_model.py`.

## Scope

- Uses only Python standard-library `sqlite3` and dataclasses.
- Reads no environment keys or secret material.
- Does not depend on `recon/`, `tools/`, or `private_refs/`.

## Capabilities

- `generate_migration_plan()` translates `TABLES` into deterministic sqlite-compatible DDL steps.
- `validate_tenant_indexes()` validates that each tenant-scoped table/index preserves the `tenant_id` leading-key contract.
- `apply_migration_plan()` applies a plan to a supplied sqlite connection or a new in-memory connection.
- `apply_to_memory_and_introspect()` applies the generated plan to sqlite `:memory:` and returns table/index names.
- `introspect_sqlite()` returns non-internal table and index names from `sqlite_schema`.

## Relationship to existing docs

The existing `worker_data_model.migration.sqlish` file remains the SQL-ish documentation contract generated by `export_sqlish_migration()`. The migrator is intentionally separate so adapters can test a real sqlite execution path without changing the DB-shaped schema docs.
