# P3 Generated Artifact Manifest Growth Round - 2026-07-07

## Goal

Make A3's gate exports more audit-grade by hashing the files generated by the Gate CLI.

Before this round, A3 already hashed input fixtures. That proved what evidence went into the gate. This round adds hashes for the files produced by the gate, which helps prove that the JSON report, Markdown report, GitHub Check payload, and PR comment artifact were not changed after generation.

## What Landed

Code:

- `services/report/a3_gate_cli.mjs`
  - Adds `buildGeneratedArtifactManifest()`.
  - Adds `--output-manifest`.
  - Writes `json_report`, `markdown_report`, `github_check_run`, and `pr_comment_markdown` artifact hashes after the files are generated.
  - Uses workspace-relative artifact paths to avoid local absolute path leakage.

Fixture:

- `fixtures/a3/p3/a3_gate_cli_generated_artifact_manifest.redacted.json`

Tests:

- `tests/a3/a3_gate_cli.test.mjs`
  - Verifies hash values match the actual generated files.
  - Verifies byte sizes match.
  - Verifies generated artifact paths do not expose local user directories.
  - Verifies the committed manifest fixture shape.

## Commercial Value

This is a small but important enterprise audit step.

A buyer can now ask: "How do I know the release gate report attached to this PR is the same report that was generated by the gate?"

A3 can answer with:

- input hashes in `audit_manifest.artifacts`
- output hashes in `a3.generated_artifact_manifest.v1`
- redacted committed evidence under `fixtures/a3/p3`
- tests proving the hashes match actual generated files

That moves A3 closer to a release sign-off system a manager, security reviewer, or compliance reviewer can trust.
